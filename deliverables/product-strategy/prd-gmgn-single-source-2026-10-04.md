## 📌 TL;DR

- **结论：可以全部用 GMGN，但要先把两条自己代码里的硬阻塞拆掉。** 数析 89 次真实调用实测**推翻了旧评估的两条结论**：① `kline` 没坏，是 `from/to` **必须传毫秒**（传秒会 HTTP 200 + `code:0` + **0 根蜡烛**，静默）；② `/v1/token/security` **根本没有** rug/wash/rat/bundler，那批风控字段在 **trenches/trending 行内**（顺带发现更强的路由 `rank?order_by=creation_timestamp`，w1 拿 50 行）。
- **两个必须立刻处理的坑**：🔴 `FEED_LEAD_RETENTION_MS = 60min`（`tracking.mjs:110`）→ feed 行最老 **0.98 小时就被删**、`outcomes` 长度 **0**；🔴 `outcomes.mjs:31` 写死 `provider!=='AVE' → return []` —— **退役而不换源 = outcome 静默归零**（本次退役最危险的失败形态）。
- **一个会直接害死人的假安全**：BSC `rug_ratio` 不是缺失，是**恒等于 0**（50/50 全 0；SOL 中位 0.244）→ 会被任何 `rug≤0.2` 门槛静默放行。**BSC 过门槛率 38% vs SOL 2% 不是 BSC 更安全，是这个字段是空的 0。**
- **最终形态多了三样**：钱包战绩（GMGN 结构性做不到而我方能做）、早期筹码「首见→当前」双时点、安全从布尔改 **7–9 项逐项明细**。其中两样**增量请求权重为 0**（字段本来就在发现流行里，只是没产品化）。
- **"能不能发现金狗"的答案从 M6 提前到 M1 开工后 25–30 小时**（样本 3–5 小时采满，唯一瓶颈是 T+24h 成熟期），前提是 M0 那五件解锁先做完。

## 1. 本轮实测的五个硬事实（含主理人仲裁）

### 1.1 🟢 配额争议已仲裁：所谓「Free 5/5」不成立

竞析发现官方 skill 与镜像文档的配额口径冲突（20/20 vs 分档 Free 5/5 · Plus 20/20 · Pro 50/50）。若实际是 5/5，`pacing` 假设偏乐观 4 倍、w5 路由只有 1 req/s，整个单源架构要重排。
**主理人实测裁决**（`.workbuddy/source-calibration/probe-quota-tier.mjs`）：burst **12 个 w1 请求 @10 req/s 全部通过**（12/12，无 429、无 ban）→ **Free 5/5 被否证**，维持 capacity ≥12 / rate ≥10/s（与 20/20 一致）。
⚠️ 推论边界：该结论**只对 w1 路由成立**。析客据此把 w5 的 `top_holders` 判为暂缓（理由正确：拿 w1 的结论给 w5 开工是越界推论）。

### 1.2 🔴 kline 没坏，是单位错了 —— T+24h 回读有解

| 调用方式 | 返回 | 判读 |
|---|---|---|
| `from/to` 传**秒** | HTTP 200 + `code:0` + **0 根蜡烛** | 静默失败，旧评估据此判"kline 弃" |
| `from/to` 传**毫秒** | 60h 老币 1h 线 = **24 根**；1m 线 = 100 根；秒级超新池 1~2 根 | ✅ 可用 |

→ 这是**整个单源化的解锁点**：AVE 唯一的独占能力（历史回读）被取代，AVE 可以退役。
→ 代价：必须加守卫——**传秒要显式报错，绝不能当成"没数据"，更不能当成"归零"**。

### 1.3 🔴 风控字段的出处搞错了（旧评估 §3.3 是错的）

- `/v1/token/security` 只给 **28 个 key**：税率 / 锁仓 / renounced / honeypot / top10。**没有 rug_ratio / is_wash_trading / rat_trader_amount_rate / bundler_rate**。
- 那批字段在 **trenches / trending 行内**（trending **50/50 全覆盖**）。
- → 风控字段**从行内取**，并且它是**零权重**（随发现轮到达）。

### 1.4 🔴 BSC `rug_ratio` 恒等于 0 —— 假安全，比缺失更危险

- 实测 **50/50 全为 0**；同期 SOL 中位 **0.244**、37/50 非 0。
- 它不报错、不留空，**会被任何 `rug ≤ 0.2` 的门槛静默放行** —— UI 上看起来就是"已评估为安全"。
- 治理（三条缺一不可）：卡面恒显「**未评估**」· **该字段不得作为"通过"输入**（只能"不否决"，不能"加分"，`poolFilters` **禁加 `max_rug_ratio`**）· 必须有一条**能区分链**的守卫测试（同一数值 0 vs 0.244：BSC 不通过、SOL 通过）。

### 1.5 🔴 两条我们自己代码里的硬阻塞（都已核实）

| 位置 | 现状 | 后果 |
|---|---|---|
| `src/tracking.mjs:110` `FEED_LEAD_RETENTION_MS = 60 * 60_000`（`config.feedTrackRetentionMs` 同值 60min，`trackStaleMs` 2h） | 观察集 **99.1% 是 feed 行**，最老 **0.98h 就被删**；`outcomes` 数组长度 **0** | 不抬它，"发现力可测量"**永远为空** |
| `src/outcomes.mjs:31` `selectOutcomeJobs` 开头 `if (provider !== 'AVE' \|\| ...) return []`，且过滤 `row.baselineProvider === 'AVE'` | AVE 退役后，**不换源 = outcome 静默归零** | 这是本次退役**最危险的失败形态**：页面会显示"暂无数据"而不是"接线断了" |

> 这两条决定了 **M0 必须先做**：它们是纯配置/接线层（工作量 S），但阻塞整个产品的第三根支柱。

|---|---|
| 一个板块一个网格 / 同地址一张卡 | 结论层 = 置顶指针（点击滚动，不复制）；早期筹码 / DEV / 安全逐项 / 战绩都是**卡片内区块**；**战绩台与源健康同为页脚状态面板** |
| 未知 ×2 不上卡 | 价格轴两侧全无 → 整行不印；聪明钱/KOL 双侧 null → 整行不印；DEV 历史缺失 → 印「未检测」而非 0 |
| 未知不冒充安全 | BSC rug 恒「未评估」；BSC `honeypot=-1` → 未评估；BSC `renounced_mint/freeze` 恒 false → **整行不印** |
| 板子宁可少 | 结论层无候选显「今天没有」；BSC 断流不补老池 |
| 表头 = 投影实测数 | 表头四数 + 评级五档 + 象限 + **新增 BSC 过门槛报数**全部投影实测 |
| 第二排序键是重要性 | 组内排序不变（侧别 → 簇大小 → 金额 → 时钟仅破平）；**战绩台排序键不含 tags、不含涨幅** |
| 降级诚实 | 顶部横幅三件套（停止时刻 / 原因 / 这是历史快照）；每卡「数据年龄」角标；🚫 **禁止出现"市场清淡""无信号"**（没数据 ≠ 数据说没有） |

### 3.3 消失的一条优势 → 换了一条更硬的

「跨源交叉验证」（竞析机会 4）作废。替代不是少一条优势，而是换一条：**单一标尺 + 双时点 + 逐项 basis**。A2/A5/A6/A7 不是四个功能，是同一个功能——把同一个数字的两个时点摆在卡上。
